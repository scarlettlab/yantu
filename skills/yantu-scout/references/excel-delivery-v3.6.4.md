# Scout Excel交付规范 v3.6.4

## 默认行为

按实际信息量选择交付载体。简短整理直接在聊天清楚呈现，不强制Excel；复杂数据生成真实可下载XLSX，正文只保留结论、关键差异、覆盖范围、证据边界和链接。用户无需在请求中复述格式参数。

| 场景 | 默认载体 |
|---|---|
| 孤立事实、概念解释、少量字段 | 聊天 |
| 单研究＋两个主要终点，能完整、清晰呈现 | 聊天，先合并重复FAS/来源等说明 |
| 合理去重后仍超过2张数据表、任一表超过6列或合计超过约20个数据行 | Excel＋聊天摘要 |
| 多研究/终点/时间点/人群形成大量重复明细，或安全事件长列表 | Excel＋聊天摘要 |
| 用户要排序、筛选、后续加工复用，或明确要求Excel | Excel＋聊天摘要 |
| 用户明确不要附件/只要聊天 | 遵从；必要时分段并标明剩余内容 |

切换线按完整数据评估，不是删行或删列的上限；不得挤长单元格、拆成许多小表或省略必要字段来规避。边界情况确实可读时允许聊天，简单说明判断，不再向用户反复询问。研究数量不是唯一标准：两项研究的三个字段可能很简单，一项研究的所有安全明细也可能很复杂。

聊天完整交付通常争取约1000–1500字以内；有Excel时正文通常约300–600字，必要预览合计最多5条、6列。篇幅目标不凌驾于完整性：不能为压缩字数漏掉用户要求，长明细转附件，保留必要推理与局限。

引用来源TXT是独立的证据清单，不是英文清单；有引用的研究报告即使不需要Excel，仍按主技能引用规则生成TXT并给链接。用户可直接阅读正文，按需下载TXT追溯。无新增来源的解释可复用有效既有TXT；用户明确不要附件时例外。标题保留来源原文，说明可用中文，不自动另做英文译表或索引。

## 防止篇幅压缩造成信息丢失

先列“用户要求/必要字段 → 证据 → 交付位置”，再写摘要。将每个要求对应到聊天段落/表格，或Excel工作表/研究编号；明确标记未公开、未读取和技术失败。超出用户研究范围的字段不为凑完整性而扩展。

可以合并重复的同一分析集说明、共同时间点和同一来源；不能合并不同观察期、人群、分母、估计策略或来源。方案定义、观察值、计算值、模型估计分别保留。检查请求涉及的研究/终点/分组组合是否全部保留；有未读续页或未交付内容时不能宣称完整。Excel文件存在不代表覆盖核验已完成。

## 工作簿结构

- 聚焦任务从一个主表开始；多模式或长详情按实际阅读需要增设工作表，不为装饰新增封面、仪表盘或空表。
- B模式选择Excel时：两列“信息项 / 具体细节”的完整详情卡；过长终点/安全信息可用带研究编号的明细表承接，主表指出位置。
- C模式：开发路径地图表可按原附件规定的阶段分表；每张主表完整保留规定列及顺序，不得把必需列拆散到多个表。明细表只承接展开内容，主表保留对应结果及明细定位。
- D/E模式：完整竞争格局表及确有必要的IIT/待确认清单；完整结论和数据来源均保留。
- 同一工作簿优先承载相关大表，默认文件名“研途Scout-主题-YYYYMMDD.xlsx”；Scout版本在适当的说明单元格或文件属性中标记v3.6.4。
- 第1行为真实表头，A列放稳定研究编号、药物名或“信息项”。不在数据表头前加装饰性大标题。标题由工作表名/文件名表达。
- 保持固定业务列顺序。确需把特别长的细节移出主表，可按稳定编号关联到明细表；不得缩写到丢失人群、时间点、对照、估计策略、分母或单位。

## 简洁阅读样式

| 项目 | 默认设置 |
|---|---|
| 正文 | 等线11pt，深灰#243442 |
| 表头 | 等线12pt加粗，白字，深蓝灰#314B5B |
| 隔行底色 | 白色 / 浅灰蓝#F2F6F8 |
| 网格与边框 | 隐藏网格线，表头下边线及必要分隔线；不加密集粗边框 |
| 冻结 | 数据表B2，即首行+首列；确需两列标识时C2。若模板已有多行表头，冻结到最后一行表头 |
| 筛选 | 启用所有数据列的筛选，不合并数据单元格 |
| 列宽 | 标识约18–24、短分类约14–20、日期约14、描述约35–60字符；按实际字体和内容微调 |
| 行高 | 普通行约24–32pt；长文本自动换行并按内容增加行高，不强行压缩字号 |
| 对齐 | 表头居中；文本左对齐且顶端对齐；数字右对齐 |

短摘要页无需机械冻结；主数据表必须核对首行首列同时冻结。超长单元格不截断，改按研究编号拆成可读明细记录；不得超出Excel单元格长度或行高限制后静默丢失内容。

## 数据与来源

- 数值保持数值，百分比保持0–1数值配百分比格式。日期可完整到日时使用真实日期，只有年月/年份时保留原始精度，不虚构日。
- NCT/CTR/研究代号、带前导0编号均为文本。预计/实际、分析集、时间点、分母、单位、CI与缺失原因保留。
- 来源编号继续对应独立TXT。所有来源URL单元格必须为真实可点击链接：优先原生hyperlink，不支持时使用HYPERLINK公式；禁止仅写普通文本URL或依赖Excel/WPS自动识别。多个来源拆成清楚的来源列/来源行，不把Markdown链接或HTML标签直接粘进单元格。
- 网页或注册库字符串只能作为数据写入，不作为公式执行。计算值与原始值清楚区分；公式仅限报告明确需要的计算或来源超链接。
- 不用颜色单独表达证据强弱或结论；相关状态必须有文字。

## 执行

1. 先按上述规则选择载体并建立内容覆盖清单，保持用户限定的数据库、研究和模块范围。
2. 简短整理直接生成聊天正文及按引用规则所需的TXT；不为了导出而增加检索量。
3. 复杂整理用可用工具生成XLSX和UTF-8引用来源TXT，核验后给出真实下载链接与正文摘要。已读取有效资料可以复用。
4. 工具不可用或生成失败时，具体说明限制、缺失文件和临时交付状态；不伪造链接，不用“内容简单”解释技术失败。

优先使用当前环境可用的电子表格能力。随附脚本支持JSON输入、多个工作表、类型、列宽、换行、冻结及超链接；它需要Node和@oai/artifact-tool，ZIP属性写入还用jszip；导出后自动调用Python3标准库检查器，检查失败则脚本以失败结束并保留内部QC记录（可用SCOUT_PYTHON指定环境已有的Python路径）。环境未提供这些依赖时用本环境的原生文件工具或Python电子表格库实现同样的规范，不要求用户处理环境。

脚本输入见 `../examples/excel-style-sample.json`。示例均为虚构样式测试数据，不可作为医学结论。

运行：`node scripts/build_excel_report.mjs report.json report.xlsx`。可选第三参数指定代表性预览目录。输入sheets数组中每张表提供name、columns、rows；列支持text/number/percent/date类型、width和numberFormat。单元格可用{value, url}生成来源链接；numeric value必须提供JSON数值。以=起始的文本按字面保存。

## XLSX结构性硬要求与导出后验收

以下为最终文件必须实际保存的结构，不是样式建议。只在生成Excel时执行；不能用代码调用记录、Table外观、PNG预览或读取库补出的默认属性代替文件本身的证据。

| 项目 | 最终文件验收要求 |
|---|---|
| 冻结 | 每张数据表冻结首行及首个稳定标识列，默认B2；两列标识时C2，多行表头按实际设置。短摘要页确无需要时可例外，但须在内部核验记录中写明表名和理由。 |
| 筛选 | 每张数据表的筛选覆盖完整表头及全部数据行；检查worksheet或Table中的真实autoFilter及表头下拉设置。Table对象、配色或排序本身不能证明已启用筛选。两列纵向详情卡作为数据表同样检查。 |
| 来源链接 | 核对所有来源URL单元格实际具有有效的原生超链接关系或HYPERLINK公式，且目标与其来源一致；不能只抽到一个好链接便忽略同表其余纯文本URL。结构核验不等同于已联网验证目标页面当前可访问。 |

生成器完成导出后，重新读取实际准备交付的XLSX，逐表检查以上适用项，并核对公式错误及文件包完整性。若之后又修改或重新导出文件，需重新检查最终版本。保留内部逐项通过/失败及位置记录；正文只需简述结论，无需输出技术日志。

优先运行随附只读检查器（仅需Python3标准库，不改写文件）：

`python3 scripts/validate_excel_delivery.py report.xlsx`

默认所有工作表均为数据表，冻结为B2或C2；多行表头、分区数据或短摘要页使用可选的核验配置JSON（见脚本`--help`），明确期望范围和例外理由。结构核验结果必须同时与内容覆盖清单核对；不得为了让检查通过而移除数据表、来源列或缩小数据范围。检查器不替代医学内容核对和代表性视觉检查。

当前环境无法运行脚本时，必须用现有工具等效检查实际导出文件；不能将“脚本不可用”视为已经通过。任一硬要求失败，先修复、重新导出并重新检查；确有无法解决的工具限制时，明确未满足项并只作临时交付，不得标为“最终交付”“全部通过”或静默降级。

真实附件可下载即满足文件交付渠道要求；Library归档不是完成条件，也不能用“已存入Library”代替上述核验。

## 交付前检查

核对载体选择与覆盖清单，确认所有所需字段有内容或明确缺口，正文清楚说明附件/分段承载的范围。所需XLSX和TXT均应已生成、非空且可读取；TXT来源编号与正文及Excel一致。以下Excel检查只对实际生成Excel的任务执行，不为了检查而强制生成文件。

核对记录数、关键编号、必需字段、来源编号、数值与缺失属性；确认文件可打开。检查每类改动的代表性视图：表头/首批记录、最长文本、来源列，确认没有截断、字号过小或越界。按上节检查保存的XLSX冻结、筛选、来源链接；未通过时执行修复或如实标明临时交付。说明技术检查与ChatGPT端真实生成体验的验证边界。
