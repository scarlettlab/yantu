# 研途Draft｜医学写作QC参考（V0.7）

更新日期：2026-09-27  
来源：整理自本目录 V0.4《医学写作QC清单》，按主提示词 V0.7 的任务模式和自然论述要求去重。  
用途：写作前后按任务查找核对点；不是每次都要运行或向用户展示的完整流程。核心执行要求已经写入主提示词。

## 1. 先选任务类型

| 任务 | 优先检查 | 常见误差 |
|---|---|---|
| 纯润色/翻译 | 原意、主语、时态、否定、比较关系、术语及数字不变 | 为了语言自然新增机制、文献或疗效结论。 |
| 局部起草 | 文件用途、读者、段落功能、具体研究缺口和项目术语 | 用通用背景三段式代替当前科学问题。 |
| 疾病背景/论文引言 | 人群、现有认识、未解决问题、研究为何切入 | 把论文摘要里的国家数、研究数或样本量机械堆进背景段。 |
| 结果/讨论 | 观察指标、分析集、时间点、比较、效应量、不确定性；解释与观察分开 | 把相关写成因果、探索性结果写成确证性获益。 |
| 临床研发文件 | 当前方案、IB、SAP、TLF/CSR 的版本与设计/结果一致性 | 药名、剂量、访视、终点、分析集或旧项目文字残留。 |
| 安全性叙述 | 暴露、事件、检查、诊断、处理、研究药措施、转归的时间线 | 混淆严重性与严重程度；漏写死亡、SAE、停药或不利结果。 |
| 监管核查 | 适用地区、文件状态、生效日期、条款原文及约束强度 | 用历史 Knowledge 或另一地区要求作当前依据。 |

## 2. 跨任务核对字段

| 层面 | 核对问题 |
|---|---|
| 任务边界 | 是否只完成用户要的段落/文件？是否保留现有模板和已确认主张？ |
| 科学含义 | 观察、解释、假设、建议各自清楚吗？是否保留不一致与不利证据？ |
| 数据 | 分母、分析人群、时间点、单位、方向、小数位、效应量/CI 与源文件一致吗？ |
| 术语 | 药物名、项目代号、疾病亚型、终点、分析集、AE 分类与当前正式文件一致吗？ |
| 证据 | 每个关键外部主张有直接且本轮已核实的来源吗？引用编号与条目一一对应吗？缺口是否标明？ |
| 监管 | 使用了本轮打开的官方来源吗？状态、地区、产品、研发阶段与条款强度匹配吗？ |
| 风格 | 本段是否推进一个具体问题？连接词和抽象壳词是否遮蔽了实际信息？ |
| 保密 | 是否只使用完成任务所需的病例/项目资料，并按所属机构政策处理？ |

## 3. 典型问题的修订方向

| 原写法（示意） | 需要核对或修改的点 |
|---|---|
| “A 指标显著升高，证明该药改善长期预后。” | 先核对研究设计、终点、观察时长和临床结局；指标变化不能直接证明长期预后获益。 |
| “发生 5 例严重 AE，均为重度。” | SAE 的严重性与事件严重程度需分别核对，不能互相推断。 |
| “受试者血压较基线下降。” | 说明测量方法、基线访视、分析人群、时间点和比较对象。 |
| “依据某指导原则，所有项目必须……” | 打开当前地区的官方原文，核对文件状态、适用品种及“必须/建议”原措辞。 |
| “研究规模很大，因此结论可靠。” | 研究质量还取决于设计、偏倚、测量、缺失、精确度和适用性；规模不能单独证明可靠。 |

示意句不是临床结论，也不是对具体研究的判断。

## 4. 何时向用户单独指出问题

存在会改变方向的项目数据矛盾、关键证据缺口、无法确认的监管适用性、原文与拟写结论冲突，或需要医学/统计/注册正式判断时，正文后用短句说明具体待确认点。普通语言润色不附完整QC记录或例行免责声明。
