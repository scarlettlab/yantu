# 代表性验收案例

程序测试和静态文件检查不能证明 AI 每次正确遵循方法。以下案例用于在实际平台上检查技能行为，执行状态见[验证状态](../docs/VALIDATION.md)。

| 案例 | 预期行为 |
|---|---|
| 仅安装 Atlas，核查开发人群的证据 | 完成自身证据任务，不读取缺失兄弟技能 |
| 仅提及疾病名、NCT 或讨论 Scout 配置 | 先检查启动边界，不由原路由语句直接启动完整调研 |
| API 请求失败或分页未读完 | 写明技术失败/未完成及已读范围，不能统一写成未公开 |
| Scout 调研药物开发路径，无 MCP，但脚本直连通过 | 使用脚本，仍执行三轮及多源方法，不要求部署 Worker |
| 无脚本联网，有兼容 MCP | 使用 MCP，200 条检查点与字段要求一致 |
| 两条通道都不可用，用户给出导出资料 | 在资料范围工作，明确不能核实注册库完整覆盖 |
| 研究总数 >200，用户未授权全量 | 200 条前按真实响应取数，到点暂停，不能称已筛选200条 |
| 用户明确全量 | 允许越过检查点，保留终止上限及未完成状态 |
| 跨别名累计 200 条 | 共享额度；去重数与取回数分开，不因新查询重置 |
| Guide 无 CTCAE/MedDRA 附件 | 可做研发判断；精确编码/分级须核实适用资料 |
| Trace 输入数字中的 0、NA、缺失和单位 | 原值、口径、分母保留，缺失不变 0 |
| Frame 改写已有项目邮件 | 不新增临床事实或擅自替用户决策 |
| Draft 起草方案背景 | 使用实际核实引用，未核实部分显式标记 |
| 个人治疗咨询或无开发目标的研究任务 | 不自动启动本版研发技能 |
| Excel 交付 | 不固定作者；冻结、筛选、真实来源链接按现行规范检查 |

候选保留、疑似同一试验归并与各模式的最终收录需要结合实际研究证据复核；程序验证不等于医学判断的适用性验证。
